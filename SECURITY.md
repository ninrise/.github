# Security Policy

At **Ninrise** (`N∞`), we take the security, integrity, and privacy of our software, services, and users seriously. We appreciate the responsible disclosure of vulnerabilities by the security community and are committed to resolving security issues right.

---

## Supported Versions

Security updates and patches are primarily applied to active, currently maintained branches and latest releases across our repositories. Please refer to each repository's individual documentation for specific branch maintenance schedules.

| Release Channel | Supported | Notes |
| :--- | :--- | :--- |
| Latest Stable Release | ✅ Yes | Actively patched |
| Prior Major / Minor Releases | ⚠️ Case-by-case | Critical security fixes only |
| Pre-release / Experimental | ❌ No | Please test against latest stable |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, pull requests, or public discussions.**

To report a vulnerability safely, please use either of the following official channels:

1. **GitHub Private Vulnerability Reporting (Preferred):**
   - If the affected repository has Private Vulnerability Reporting enabled, navigate to the **Security** tab of that repository.
   - Click **Report a vulnerability** to open an advisory draft directly with the maintainers.
2. **Dedicated Security Email:**
   - Send your report directly to our security team at **[`security@ninrise.com`](mailto:security@ninrise.com)**.
   - Alternatively, you may reach maintainers via [https://github.com/ninrise](https://github.com/ninrise).

### Information to Include in Your Report
To help us triage and resolve the issue quickly, please provide as much detail as possible:
- Type of issue (e.g., buffer overflow, SQL injection, cross-site scripting, privilege escalation).
- Full repository path or source code reference where the vulnerability exists.
- Step-by-step instructions or minimal proof-of-concept (PoC) to reproduce the vulnerability.
- Any potential impact or attack scenario.
- Suggested remediations or mitigations, if known.

---

## Our Commitment

When a security vulnerability is reported responsibly:

- **Timely Acknowledgment:** We aim to acknowledge receipt of your report within 48 to 72 hours.
- **Transparent Assessment:** We will investigate and provide an initial assessment of the issue and severity.
- **Collaborative Remediation:** We will keep you informed of our progress as we work on a fix.
- **Credit & Recognition:** We are glad to credit reporters who practice coordinated, responsible disclosure once the patch is published (unless you prefer anonymity).

---

## Safe Harbor

We consider security research conducted in good faith under this policy to be authorized. We will not pursue legal action against researchers who:
- Make a good-faith effort to avoid privacy violations, destruction of data, and service interruption.
- Give us reasonable time to remediate the vulnerability before public disclosure.
- Do not exploit the vulnerability beyond what is strictly necessary to establish proof-of-concept.
